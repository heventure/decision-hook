# 首版设计

## 开工前定下来的事

- 只做 Pi、Vitest 和 LM Studio，从已执行的测试工具结果触发。第一版只增加分诊建议，主智能体仍负责定位和修复。若实验表明建议只增加等待时间，停止扩展宿主和协议，先重新选用例。
- 固定三个标签。  **断言失败**表示有明确的断言不匹配或测试明确报告失败，且可排除运行器启动失败。  **环境异常**表示主要证据指向依赖、运行时、配置、权限或执行环境阻断。  **证据不足**覆盖信息缺失、多种同样合理的原因和超出标签范围的情形。给标注者写出每类的正例和反例，保留争议样本。
- 保留原工具结果和状态。规则证据明确时跳过模型。端点超时、协议不匹配、响应缺字段、未知标签或低置信度时跳过模型建议，并留下本地可诊断的简短原因。每次工具调用最多发起一次决策请求。
- 首发默认本机运行。只发送分类所需的短诊断片段，优先处理结构化字段。日志只记录匿名用例标识、标签、耗时和回退原因。源代码、完整会话、环境变量和凭据都排除在默认输入和日志之外。加入远程端点时再明确披露数据去向和认证方式，由用户显式启用。

## 可以边开发边确定的事

先用两个可控的真实运行，分别触发一次断言失败和一次环境异常。读取 Pi 实际传给扩展的事件，确认命令、工具调用 ID、退出状态和输出片段能否可靠取得。优先读取已有的结构化报告。若通用 Bash 结果无法可靠识别，就把首版限定为显式的 Vitest 运行入口，仍在测试结果到达时自动分类。

事件字段提取、提示词、诊断片段长度、超时、置信度门槛、最低宿主版本和结果展示样式随样本与实测迭代。超时上限先按能接受的额外等待时间设定，阈值只用调试集调整。发布前在冻结的留出集验证一次。初版用文本附在结果旁，专用 GUI、自动通用触发和其他宿主以实际使用反馈决定。

## 协议与适配顺序

| 顺序 | 协议 | 支持策略 |
|---|---|---|
| 首发 | Jev / System One | LM Studio POST /v1/systemone。请求用 state 和按题名映射的 questions，首版只用 choice。现有基准已有请求样例和实测结果。配置为协议、完整 endpoint URL 与模型 ID。 |
| 第二项 | OpenAI Decisions | POST /v1/decisions。请求用 input 和 questions 数组，逐题从答案数组取值。先用契约夹具，再用有权访问的真实端点验证，随后才在 README 声明支持。为远程请求加用户显式配置与凭据引用。 |
| 后续 | Jev 风格的供应商端点 | 核实认证、路径及字段后再加入兼容清单。Venice 的 /api/v1/decisions 接收 Jev 风格的 state 和问题映射，可作为复用 Jev 适配器的候选。 |

插件内部只需要统一的任务字段、标签、模型给出的置信度或概率（实际返回时才记录）和回退原因。使用显式协议配置，避免用 URL 名字猜请求或响应格式。概率值由各供应商定义，门槛按模型和场景校准。用适配器隔离请求和响应差异，等第二种协议确实接入再提炼公共代码。
